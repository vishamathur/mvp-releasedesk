Skill: security-review
Read the change (intake text, estimate, or PR diff via GitHub). Check KYC data handling, auth, secrets, prompt injection and LLM output trust (OWASP LLM Top 10, MITRE ATLAS). Count release blockers. Save pid.slice.security.<stage>.<id> and sec.blockers.<id>.

Also read the pull request comment that starts with `## owasp-review v1` (`docs/security/owasp-review.md`). The machine JSON is the `owasp-review.v1` block. The selector checks only the controls the diff can affect; every other control is NOT_APPLICABLE with reason `not selected: no matching change`. Confirm each grounded failure in `failures[]`. Outcome `remediate` hands those path:line fixes to Builder. Outcome `needs-human` is the exception list, not a pass. A missing, failed, or skipped review is never a pass and never auto-proceed. You do not type the security-compliance gate; a human does. Grok stays advisory.
